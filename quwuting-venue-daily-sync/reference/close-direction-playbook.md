# 关门方向（白名单）范围判定细则（close-direction-playbook）

> 由 SKILL.md Step 3B 迁出的细则与实证。**核心口径（白名单 + 城市硬边界）以 SKILL.md 红线 3 为准**。

## 1. 为什么需要「范围细化」

`coveredCities` 是**城市名级**的粗集合，而平台城市是**地级市**、舞讯报到的是**县市级 / 市区**。
直接按「该城全部门店」取差集会把**舞讯根本没报到的下级区域**整片拖进来 —— 误伤。

## 2. 三条收敛规则

### 2.1 县级市 / 县独立判定（不随母城）

门店 `district` 形如 `XX市` / `XX县`（平湖市、嘉善县、启东市、常熟市、溧阳市、江阴市、昆山市、
句容市、丹阳市、仁寿县、桐乡市、海宁市…）→ **只有该县市名本身被某源报到才纳入**；
未被报到 = 今天没有该地的数据 → **不动**。

> 反例：按「嘉兴市」把平湖/嘉善/海盐一起暂停 = 误伤（这三地舞讯压根没报）。

### 2.2 市辖区随母城

`district` 形如 `XX区`（崇川区、雨花区、南湖区…）→ 跟母城走。

### 2.3 母城被「按区枚举」时只认枚举的区

某源把该城拆成区逐行列（2026-09-10 实测：**重庆**列 江北/九龙坡/南岸/渝中/两江/沙坪坝/万州/铜梁；
**成都**列 金牛/青羊/锦江/成华/武侯/温江/郫都）→ 该城**只对有名单的那些区**做推断，
其余区（重庆永川/渝北、成都新津/双流…）不动。

> ⚠️ **枚举名对不上平台真实 `district` 时退回整城**：西安用的是「城中/西郊/东郊/南郊/北郊」
> （方位，不是区名），若照枚举过滤会把整个西安市判空 → 判定 `ENUM_ACTIVE` 时先验证
> 「枚举名 ∩ 该城真实 district ≠ ∅」，否则视为未枚举。

## 4. 单源覆盖城市（重要预期，不是 bug）

两个源的覆盖城市表天然不同：A 源（市井慢时光）~29 城 / B 源（百事通）~135 城。
**只有 B 源报到的那批城（南昌/南宁/东莞/深圳/青岛/郑州/石家庄…）永远 `|S| = 1`**
⇒ 开门与关门两个方向都不自动写库，只能进人工清单。

> **汇报时必须显式说明「本轮 N 个城因单源覆盖未做任何自动写库」**，否则用户会以为漏跑。

## 5. 提交前自检清单

1. 城市逐个核对**确有门店名单**（「未有待更新 / 待定 / 无商家信息」视同未覆盖）；
2. 打印 **暂停 N 家 + 城市分布**；
3. 打印 **各城 S 分布**（`城市 → {A,B}`）——某批城市 S 集体退化成单元素 = 城市名口径没归一；
4. 规模对照：预期 **40–80 家 / 10–20 城**（09-10 首跑 54 家 / 13 城）。
   **跑到几百家先停下回头查**（多半是城市名口径没归一或范围细化没做）。

> 🔧 **已脚本化（2026-09-14）**：`scripts/qw_analyze.py` 输出上述全部自检项（覆盖城市、
> 仅有城市名无名单的 header、县级回挂母城、暂停家数+城市分布、守卫剔除明细），
> 且规则 2.1/2.2 由**平台 district 数据驱动**（`county_to_city` 反查）——不再手抄县级→母城映射。
> ⚠️ 与地级市同名的县要排除（`长沙县` vs `长沙市`）：**母城被点名 ≠ 该县被点名**，脚本已内置该判据。

## 6. 重跑语义

`batch-suspend` 对已是 SUSPENDED 的条目**幂等跳过**（只有 OPEN 会动），所以发现漏跑/口径修正时
**重提全量即可，无需自己算差集**；想让汇报口径干净（只报本轮真实新增）再自行 diff 上一批 venueId。
`status-reverse` 同样幂等（已 OPEN 跳过），两个方向互不干扰、可放心重跑。

## 6.5 写库后核验：全量 export 逐店 diff（2026-09-14 立为固定动作）

**为什么**：接口返回的 `total/suspended` 只证明「提交了多少」，**不证明「范围对不对」**——
白名单口径最大的风险不是写失败，而是**写错了范围**（多写/少写），而接口在这一维度上是瞎的。

**做法**：
1. 写库**前**拉一份全量 export 存快照（`--export-cache` 顺手就用它）；
2. 写库**后**再拉一份；
3. 逐店比对 `status`，输出 diff 列表。

**通过判据**（三条齐备才算过）：
- diff 条数 **== 应变更条数**（恢复家数 + 暂停家数）；
- 门店总数不变（无增删）；
- **「无名单 header」城市零变更**（如 09-14 的泰州/宁波），县级市未报到的（扬中/诸暨）零变更。

**09-14 实证**：diff = 59（56 `OPEN→SUSPENDED` + 2 `CEASED→OPEN` + 1 `SUSPENDED→OPEN`），
总数恒 1099，泰州/宁波零变更；状态分布 OPEN 305→252 / SUSPENDED 139→194。

> 同一份 diff 数据也是**汇报与 run-history 的数字来源**——把这三行贴进实录，下一轮就有对照基线。

## 7. 已知代价（用户已接受）

白名单口径下「舞讯某日漏报某店 → 该店被误标暂停」。09-10 实证：5 家用户本周亲自核实过的门店
（鞍山舒馨/富琳、沈阳新·合·富/夜色、常州梦都）因当日舞讯未点名被暂停，**用户拍板保留暂停**
（按新口径统一，下一轮被点名会自动恢复）。用户若要求「执行前先看暂停规模再放行」，
可在表⑤ 前加确认闸门（当前口径 = 直接执行）。
