## 真实事故与复盘

### 菲琳 / 玫瑰天堂「明明营业却显示停业」

平台快照为 CEASED 而实际已 OPEN，用户投诉。→ 催生「每日跟进舞讯、状态保鲜」这条主线，
以及「门店时效性基本是一天当天的」口径。

### 2026-09-01 · 翻页漂移导致 10 家「假新店」

`searchRanked` / `searchRankedNoLocation` 的 `ORDER BY HEAT_SCORE DESC` 无 id tie-break，
热度分大量为 0 时排序键重复，翻页边界漂移——实测 recommended 翻页拉成都 107 家只返回 81 家
（漏 26 家），连带误判 10 家「假新店」。修复 = 两个排序补 `, v.id DESC`；export 的
`findExportPage` 用 `id ASC` 天然稳定。**教训已写进 SKILL.md**：候选拉取必须稳定排序。

### 2026-09-04 · 滁州 4 家险归马鞍山

全量拉取后未核对平台城市词表，险些把平台未覆盖的滁州条目混入邻近的马鞍山比对。
→ 立规：**全量拉取后必须用 `GET /venues/cities` 核对，平台未覆盖城市的舞讯条目剔出比对集**。

### 2026-09-08 · 昆山新茶吧 #1114 单源反转回退

仅 C 源点名即执行反转，事后回退。→ 催生 09-09「单源不写库」红线（系统性收口），
09-10 进一步收紧为「全源一致」。

### 2026-09-10 · 城市名口径未归一（静默失败）

A 源「成都/重庆」vs B 源「成都市/重庆市」，`covered` 求交为 ∅ → 双源被判单源 → 成都/重庆**整城
静默跳过**（不报错）。修复 = 统一去「市」归一；成都补出 3 家暂停。→ 立规：**提交前打印各城 S 分布自检**。

### 2026-09-11 · 第 2 跑（本地 develop）

- **输入**：A=市井慢时光 30 城 / B=百事通长文本 14:00 ~100 城，双源城市 29 个；mention 622 条
  （matched 394 / UNMATCHED 225 / 守卫跳过 3）。
- **结果**：**反转 4**（梦都 #791 / 星夜之约 #887 / 繁花 #891 / 颐和 #978）+ **新店 3**
  （323 #1231 江阴 / 海尚壹号 #1232 南通 / 沙皇酒楼 #1233 绍兴）+ **暂停 12 / 4 城**
  （杭州 1 · 嘉兴 1 · 无锡江阴 1 · 绍兴 9）。公告 #31 create+publish。
- **🔴 越权事故（当轮晚些时候用户驳回）**：3 家新店按旧口径（「全源一致直接 batch-create」）被
  **自动建档**，用户明确「**没有允许禁止新增**」——即定时口径变更：
  - 表③ 执行 = **待放行清单**（只列不建），用户放行后才 `batch-create`；「全源一致自动建档」作废；
  - 红线 4 改写为「禁止自动新增」；公告章节同步为「新店放行后随放行环节询问」。
  - 3 家处置（删除 / 保留）与公告 #31 修订以用户指示为准；后端**无门店删除接口**，删除须 DB 层。
- **🐛 县级 header 两坑（细则进 matching-playbook §5）**：①江阴/昆山/句容/丹阳/海宁/仁寿等独立
  header 须回挂母城候选（按 district scope 过滤）——否则喜见/K2/金佰莉误判 UNMATCHED，其 OPEN
  正本险落表⑤（镇江 3 家险误伤）；②M 统计直接用命中源集合，按平台城市过滤会把县级点名清零
  （星夜之约/繁花漏反转、汇锦/盛邦被记成关门候选）。
- **规模说明**：暂停 12 家低于 40-80 预期带宽 = 正常（09-10 已暂停 54 家不重复 + 当日 A 源
  覆盖面扩大）。**预期带宽应视为量级参考而非硬指标**。
- **表②**：4 条守卫再确认（南宁天涯 #543 / 南宁TT #547 / 南昌丽莎 #1224 / 滁州丽莎 #1174，
