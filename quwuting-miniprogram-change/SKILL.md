## 1. 仓库硬约束（先看）

- 原生小程序 + TS + glass-easel，**生产渲染 = WebView**（Skyline 仅调试能力）；页面一律 `Component()`
- **禁 ES2020+ 语法**（`??` / `?.`）；`strict` 全量；布局用 `rpx`，仅 hairline 用 `px`
- **页面可以 `import { XxxVM } from '../../components/xxx/xxx'` 复用组件的类型**（2026-09-10 快讯信息流确立）：
  纯类型导入被 tsc **完全擦除**、产物里不产生 `require`（改完 grep 一下页面 `.js` 的 `require(` 可自证），
  故不存在运行时耦合/循环依赖。**禁止因为"跨目录"而手抄第二份类型定义**——组件定义的展示契约
  （如 `ReactionChipRowVM`）就该有唯一一份，宿主只负责派生数据。
- **`.js` 是 `.ts` 的编译镜像，必须同步提交**（仓内 `.js` 与 tsc 产物逐字节一致）；
  **先改 `.ts`，再回拷 `.js`，禁手改 `.js`**（手改必与 tsc 产物漂移）
- 改设计/流程/约定 → 同步 `AGENTS.md`（索引行 + 最小事实条目）与 `docs/agents/NN-*.md`
- **并发提示**：本仓常有多会话并行改同一批文件，编辑前先 `git status --short` + 看文件 mtime；
  **改完自查 `git diff --stat` 时，输出里会混入其他会话正在改的文件（陌生文件≠你的改动）**——
  绝不要整体 `git add -A` / 整体还原 / 顺手"修"别人的文件；收尾汇报时也只说自己动过的那几个文件。
  （2026-09-10 实录：本会话改 index/venue-detail/venue-card，同时段另一会话在改 `danceTimer`/`43 号文档`；
   两端互相在日志里看到对方的半成品 TS6133，谁都没碰谁的文件。）
- **「轮次编号」与「§号」是两套编号，都要防撞（2026-10-06 实录）**：`docs/agents/43-*` 里的
  **"第 N 轮"藏在行文里、不在标题里**，只 grep 标题查不出来。实测：写完一整节才发现自己标的
  "九十轮"早被 2026-10-03 的 §83.6 占用（同一文件、同一编号、两件不同的事），只好顺延到九十四轮。
  **取号唯一依据 = 已注册编号**（`grep -rnoE "第?九十[0-9]?轮" docs/agents/*.md` + 读 `AGENTS.md`
  索引行尾部的最新轮次），**不是**"我数着应该是第几轮"；撞号后**先注册者为准、后注册者顺延**，
  并留痕。**动手写文档前先把两个水位各看一眼**（§号水位 = `grep -oE "^## [0-9]+\." <file> | tail`）。
- **同一文件的多处 `Edit` 必须逐条串行发出（禁在同一条消息里并行）**（2026-09-16 实录）：同一条消息
  对 `VenueService.java` 并发发 3 个 `Edit`（加 import / 加字段 / 改方法），其中**加 import 那个静默丢失**
  ——工具返回 `Successfully edited`，但内容没落盘，直到 `./mvnw test-compile` 报
  「找不到符号 `VenueSyncAliasRepository`」才暴露（表现像"我明明加了"，实际文件里没有）。
  **判据：工具报成功 ≠ 改动已落盘；同一文件的多次编辑一律串行，改完立刻用 Grep 复核关键锚点再往下走。**
  跨文件并行无此问题（不同文件无写冲突），可以放同一条消息。
- **`git diff` 是"相对 HEAD 的净差异"，不等于工作区现状**（2026-09-11 实录）：本仓常见
  **前一轮同主题改动尚未提交**——本轮要改「账目方向」时，`LedgerEntry.direction` /
  `SessionRole` 等已在工作区文件里，但不在 HEAD 里，`git diff` 会把它们算作"本轮新增"。
  **判据：判断"某字段/函数是否已存在、是否还有引用"一律读工作区文件内容（Grep/Read），
  禁据 HEAD、`git diff --stat` 的行数或 `git log` 推断**——否则会重复新建已存在的机制，
  或在 diff 里把自己的删除误读成别人的改动。同理，收尾汇报改了什么，也以"我实际编辑过的
  段落"为准，不以 diff 行数为准。
- **语义演进的存储迁移口径 = 同键 + 兼容读，禁建第二个键**（2026-09-11 实录：`qwt_dance_role_v1`
  从"会话身份 guest/partner"收窄为"记账方向 expense/income"）：一个事实只许一处落盘，
  值域变化靠**读取时兼容旧值（只读不回写）**收敛；新建 `*_v2` 键 = 两条真值来源，
  迟早有一处没同步（本仓红线）。
- **本机 `grep` 是 BSD 版，不支持 `\|` 交替**（2026-09-11 实测，连续踩三次）：`grep -n "a\|b" f`
  **静默返回空**（退出码 1，看起来像"没有匹配"）⇒ 会误判"代码里没有这个引用"。
  **一律用 Grep 工具（ripgrep）或 `grep -nE "a|b"`**；排查"某符号是否还有引用"这类问题尤其危险。
  **同理不支持 `\b` 词边界**（2026-09-14 再踩：`grep -E "^\.(feedback-title)\b" app.wxss`
  明明有定义却返回空，一度误判"全局原语存在但未定义"）——词边界要么省掉（改用
  `^\.feedback-title[ {,]`），要么直接用 Grep 工具。**判据：grep 返回空 ≠ 不存在，
  先换工具复核再用这个结论。**
  **又一次踩在同一个坑上（2026-09-14 五十九轮）**：`grep -n "spend\|账本\|dance-ledger" AGENTS.md`
  返回空，据此差点得出"AGENTS.md 里没有 44 号索引行"——实际那行 6559 字符、就在第 92 行。
  **改索引类文档前，先跑一次 Grep 工具确认锚点存在，再动 `Edit`。**
- **`AGENTS.md` 的索引行是超长单行，`Read` 读不到尾部**（2026-09-14 实测：44 号那行 6559 字符，
  Read 输出成 `[truncated]`）⇒ **改索引行不能用 Read 取 `old_string` 锚点**（拿到的是假原文）。
  取锚点的正确姿势 = 用脚本打印该行尾部原文：

  ```bash
  python3 -c "
  l=open('AGENTS.md',encoding='utf-8').read().split('\n')[91]
  print(len(l)); print(repr(l[-400:]))"
  ```

  改完同样用脚本断言落盘（`python3 -c "print('本轮关键词' in open('AGENTS.md',encoding='utf-8').read())"`），
  别只看 Edit 返回。**同族判据：工具的"没显示"不等于"不存在"**——Read 的截断、grep 的静默空
  返回、Edit 的假成功，三件事都能伪装成"已完成"。
- **`Edit` 工具偶发"假成功"**（2026-09-11 实测一次）：返回成功但内容未真正落盘
  （当时是往 theme.ts 插一行模块级变量，随后 tsc 报 `Cannot find name` 才发现）。
  **改完关键文件立刻用 Grep 工具回读确认**（别只看 Edit 的返回）；`tsc` 是第二道保险。
  **同一条消息里并发多条 Edit 时更易命中**（2026-09-11 再遇：一个脚本内多处同名替换只落了一部分，
  汇总返回却是"全部成功"，逐条 grep 才发现残留）——并发编辑后**每条都 grep 验证磁盘**。

## 2. `.ts` → `.js` 镜像回拷标准动作（关键，别漏）

**2026-09-11 起首选一条命令**：`npm run mirror:js`（`scripts/mirror-js.sh`，临时
outDir + 只回拷有差异文件已脚本化）。⚠️ 依赖 `tsconfig.json` 显式
`"rootDir": "./miniprogram"`（TS7 漂移后 TS5011 修复，2026-09-11 实录）——TS
大版本升级先查 mirror 链路。产物映射**不带 `miniprogram/` 前缀**
（`/tmp/qwt-ts-out/services/...` ↔ `miniprogram/services/...`）。

脚本坑点（2026-09-11 实录）：①脚本内 `$MODE：`/`$rel：`/`$dst（` 等「变量
紧贴全角标点」写法在部分 locale 下被 bash 吞进变量名 → `unbound variable`
挂脚本，已全部改 `${VAR}` 形式；②该脚本曾被 Edit 工具假成功（mtime 更新但
内容回滚），`perl -pi` 直写才落盘——**改脚本后务必用 Bash `grep` 验证磁盘
内容**；③精确模式传多路径时计数显示「1 个」是已知显示瑕疵，不影响回拷；
④**整个目录都是新文件（untracked）时脚本静默跳过**（2026-09-14 实录，新增
`pages/bulletin-landing/` 五件）：git status 把新目录聚合显示成目录级
`?? pages/bulletin-landing/`，脚本按「路径以 .ts 结尾」提取不到文件名 ⇒
该页 `.js` 不会回拷且**无任何报错**；`services/` 下的单个新文件不受影响
（显示为 `?? services/xxx.ts`）。**判据：新建页面目录后，回拷完必须
`ls pages/<name>/<name>.js` 断言存在**——缺失就手动走下方等价流程
（`tsc --outDir` + `cp` 单文件）；新建**单文件**（service/常量）不受此坑影响。

手动等价流程（脚本不可用时）：

```bash
cd /Users/yangxin/Downloads/xcxWork/quwuting
npx tsc --noEmit                       # ① 类型检查（0 错误才算过；typings 环境性错误可忽略）
rm -rf /tmp/qwt-ts-out                  # ② 全量编译到临时目录
npx tsc --outDir /tmp/qwt-ts-out --rootDir ./miniprogram
# ③ 首次使用/存疑时，先验证产物与仓内一致（挑一个未改动的文件）
diff /tmp/qwt-ts-out/services/viewport.js miniprogram/services/viewport.js
# ④ 只回拷本次改动的文件
cp /tmp/qwt-ts-out/components/xxx/xxx.js miniprogram/components/xxx/xxx.js
git diff --stat -- <改动路径>            # ⑤ 确认只动了预期文件
```

若 ③ 有差异，说明仓内产物已漂移（历史手改），**不要**顺手全量回拷——先问用户，只处理本次涉及的文件。

**判读回拷结果的两条经验（2026-09-10 实测）**：
- **`types/*.ts` 改纯类型/接口字段 → `.js` 零差异是正常的**（类型不产生运行时代码），
  不要因此怀疑"编译没生效"。判据：`diff` 空 != 失败；只要 `tsc --outDir` 退出码 0 且
  该文件的 `.js` 在产物里存在，就是没有运行时变化。反过来，**若业务逻辑文件 `.js` 也零差异，
  才说明真没生效**（大概率改错了文件/漏了 `--rootDir`）。
- **回拷清单以"改动文件里含运行时代码的"为准**：`.wxml` / `.wxss` / `.json` 不进 tsc 产物，
  直接编辑即可（无需回拷）；只有 `.ts` 需要。

改完 `git diff --stat -- <改动路径>` 只应出现本次动过的文件；本仓常有多会话并行，
输出里混入陌生文件别去碰（见 §1 并发提示）。

### 3.0 ⚠️ 仓内缺 typescript ⇒ 链上必有两道**恒定**红灯（2026-10-06 复核，仍未修）

`quwuting/` 的 `package.json` / lock **未声明 typescript**，`node_modules/.bin/tsc` 不存在。
后果两处，都与你的改动无关，**别误判成自己改坏了**：

1. **链必断在 `check:empty-state`**：其 behavior 半段（`scripts/check-empty-state-behavior.js`）
   先找仓内 tsc，找不到就回退 `npx tsc`（落到 5.9.x），而它传的 `--ignoreConfig` 是 **TS 6.x
   选项** ⇒ `error TS5023: Unknown compiler option '--ignoreConfig'`，`&&` 链**就此中止，
   其后十余道一道都没跑**。「日志里 13 条 ✓」≠ 全绿，这正是最容易被读成"通过了"的假象。
2. **`check:mirror` 恒定红**：`scripts/check-mirror.js` 硬编码
   `path.join(ROOT, 'node_modules', '.bin', 'tsc')`，不存在即 `exit 1`（只报「先执行 npm install」）。

**不装依赖也能完成验证的等价做法**：

① 镜像一致性 —— 用隔离工作区的 tsc 全量编译后逐个 `cmp`。它比 `check:mirror` **更严格**
（不容忍 `exports.*` 前导行顺序差异），此处零差异 ⇒ 那边必过：

```bash
cd <quwuting 仓>          # 本机例：/Users/yangxin/Downloads/xcxWork/quwuting
export PATH="$HOME/.workbuddy/binaries/node/workspace/node_modules/.bin:$PATH"   # tsc 5.9.3
TMP=$(mktemp -d) && tsc --outDir "$TMP" \
  && find miniprogram -name "*.ts" -not -path "*/node_modules/*" | while read ts; do
       rel="${ts#miniprogram/}"; dst="miniprogram/${rel%.ts}.js"
       [ -f "$dst" ] || echo "MISSING $dst"
       cmp -s "$TMP/${rel%.ts}.js" "$dst" || echo "DIFF    $dst"
     done; rm -rf "$TMP"
```

噪声（无害，勿追）：`components/qwt-icon/icons.d.js` = `.d.ts` 的产物，不是运行时文件。

② 补跑断点之后的门禁 —— 逐道跑，别整链重跑（清单以 `package.json` 的 `check` 链在
`empty-state` **之后**的项为准；下面为 2026-10-06 实测的 17 道）：

```bash
for g in z-stack location scrollview-flex popover-width fold-reveal bottom-track dance-timer \
         direction-vocab venue-card press-feedback auth-session first-paint-auth first-frame \
         es-syntax token-mirror presence page-enter; do
  npm run check:$g > /tmp/ck-$g.log 2>&1 || echo "RED check:$g"
done
```

⚠️ **一次跑十几道容易撞上工具的超时（实测 3~4 道即可能被 SIGTERM / exit 137）**：分批跑，
或 `run_in_background` 起来后去干别的。**别把"SIGTERM 中断"读成"门禁红了"**——它连结论都没给。
判据：日志文件 `/tmp/ck-$g.log` 存在且内容完整才有结论，否则那道门禁等于**没跑**。

⛔ 真正的修法 = 在 `quwuting/` 装 typescript（并统一 `--ignoreConfig` 的版本前提），属工程决策，
**别在业务改动里顺手做**（`node_modules` 已是 gitignored，临时软链只能骗过 `check:mirror`，
骗不过 `--ignoreConfig`）。

### 3.1 两个「接线完整性」类门禁（新增同类东西时先看这两条）

- **列表筛选维度 = `check:list-filters`（`scripts/check-list-filters.py`，2026-09-20 新增）**：
  首页「筛选」面板是加法式结构，一个维度生效需要**六处同时接线**——① data 声明
  ② wxml `bind:tap` handler（且 ts 里真有该方法）③ `refreshFilterDerived` 的 `filterActive`
  ④ `fetchVenues` 的 `listVenues({…})` 载荷 ⑤ 同方法的 `requestKey` 指纹（**漏这条 = 参数
  变了不重拉，最隐蔽**）⑥ 两条复位路径（`resetPanelFilters` 面板内 / `onClearFilters` 全部，
  **两者范围刻意不同**：面板按钮不越权清 `statusFilter`）。
  **新增筛选维度必须在本脚本 `DIMENSIONS` 表补一行**（C 组 fail-closed 会拦），
  取值里 `in_filter_active=False` / `in_panel_reset=False` 是有据的刻意例外（`statusFilter`），
  不是漏写。**判据可迁移**：断言若"两处任一满足即可"，它测的就不是它想测的那一处——
  本脚本的载荷与指纹必须**各自切出唯一承载处**（`listVenues({…})` / `const requestKey … .join('|')`）
  再断言（2026-09-20 变异测试 M2 一开始正是漏在这上面）。

  引擎加一个模式/枚举很容易看起来"只是多一个分支"，但它会**同时**改动下面这些面——漏掉任何一块
  都会留下"半套口径"（页面显示一套、账本记另一套、门禁只测第一套）：
  1. **取值单点**：新模式必须从**同一个取档函数**派生（本仓 = `pickShortestTier`），
     禁在页面里读 `tier.mode` 自判——那会与引擎的取档口径分叉；
  2. **算式/文案的每一支**：老的"三支"会变成四支（分钟式 / 档数式 / 比例式 / 门槛句），
     每支都要有**自己的恒真判据**（比例式的容差与其余支不同——因为金额是 floor 的）；
  3. **哪些读数该"消失"**：新模式可能与某个既有读数**数值恒等**（本仓：折算式下
     `折算额 ≡ 计费额`）⇒ 那个读数必须**不渲染**，并为此写一条**机器判据**
     （否则后人只会觉得"这里少了个数"）；
  4. **哪些偏好该"不提供"**：老偏好可能在新模式下无意义（凑整的前提是"有档"）——
     在派生处加模式条件，并在文档写明"不是漏了，是不适用"；
  5. **持久化签名的兼容形态**：给预设/标识加字段时，**老形态必须保持可识别**
     （本仓 `preset:M:P` 对默认模式不变、新模式才加后缀）；改形态 = 老设备认领全落空
     = 凭空多出一条重复项（§12 破坏性清退的翻版）；
  6. **门禁**：老断言会**同时**在"数量"与"模式"两处失效——把它们**拆成两条事实**
     （"墓碑不复活" + "新条目自动落到老设备"），别用一个数字断言承担两件事；
     段内断言改成**与模式无关的性质**（本仓：填色"已走+剩余=量程 / 格内递增 / 终点即跳变点"），
     否则每加一个模式就要重写一遍量程期望值；
  7. **穷举的规则表要加新模式**：`rules` 数组里补两三条新模式规则（含"除不尽"的病态值），
     老断言才会真的覆盖它。

     给某类规则加条件时，只关掉**渲染条件**是**半套改动**——金额/账目那条路还在按老逻辑走。
     实录：加了"折算式不提供凑整"后只改了 `roundCanOffer`（显不显示），而 `payableCost`

     做法：把条件**下沉到派生单点**（本仓 = `resolveRoundStepForTiers`），让"算"和"显示"读同一个值；
     页面上不再出现第二个模式比较——**同一件事两个判据 = 两个漂移点**。

  （根因在抽屉，不在按钮）。**判据：凡"内容会随业务增长"的容器，都要问一句"它满了会怎样"**
  （滚动？压缩？截断？），并为它写一条**结构性门禁**（本仓 = H1：子项 `flex-shrink: 0` + 容器仍可滚）。
  同类高发地：可滚动抽屉、列表行、`max-height` 容器、`flex` 列的定高区域。

- **验证红线（2026-09-02 用户明确）**：只做静态验证（编译 / 类型 / 门禁 / 零依赖静态检查）。
  **禁**连真库跑接口、端到端场景、启动应用做运行期验证；行为与观感交用户真机。

- **零结果空态 = `check:empty-state`（**结构 + 行为双门禁**，2026-09-30 新增）**：
  `python3 scripts/check-empty-state.py`（结构）+ `node scripts/check-empty-state-behavior.js`（行为），
  由 `npm run check:empty-state` 串联。**为什么要两道**：结构断言（声明唯一 / 四向一致 / 模板零判据 /
  派发分支齐备）**放不出"优先级写反了""覆盖集合为空仍判未覆盖""已覆盖城市被误判"** 这类错——它们不改
  结构，只让用户看到错的那句话。**判据：凡"多分支 × 文案/文案级行为"的契约，结构门禁之外必须补一道
  行为门禁**（把纯模块 tsc 出来直接 require，断言输入→输出矩阵）。
  两条实操经验（本轮实测，省时间）：
  1. **行为门禁只编译被测模块的依赖闭包，禁整仓编译**：`tsc <单文件> --ignoreConfig --outDir <tmp>
     --rootDir miniprogram --module commonjs --target es2017 --skipLibCheck`
     —— 整仓编译会把**别人在飞改动**的类型告警连成你的红灯（本轮实测：并发会话改 `venue-detail.ts`
     中途留了 8 个 TS6133，`tsc --outDir` 直接失败）。单文件编译后只落 `utils/xxx.js` + 依赖闭包，
     判据与被判对象不再有无关耦合。（`--ignoreConfig` 必须加：仓库有 tsconfig 时命令行给文件会报 TS5112。）
  2. **变异测试用仓库副本跑，别在原地改**：`rsync -a --exclude node_modules --exclude .git <repo>/ /tmp/mut/`
     + `ln -s <repo>/node_modules /tmp/mut/node_modules`，再跑副本里的门禁脚本（脚本用
     `dirname(dirname(__file__))` 自定位 ROOT，所以副本里跑读的就是副本文件）。原地做变异会与
     **并发会话**抢同一个文件（本轮实测：动手期间另一会话正在改 index.ts / city-picker / venue-detail），
     一旦撞上就把人家的在飞改动覆盖掉。还原用**内存快照 + 哈希校验**，别用 `git checkout`（那会连
     未提交的在飞工作一起丢）。

- **改动"被门禁保护的文件"⇒ 必须同步该门禁的变异自测锚点（2026-10-03 实录，两条锚点同时失效）**：
  本仓门禁普遍带**变异自测**（往源码里注入违规、断言门禁真的会拦），而变异靠**文本锚点**定位：
  `("标签", "文件", old, new)` 里 `old not in src` ⇒ 报「自测锚点失效」。于是**删/改一个方法、
  改一行 behaviors 列表，都会连带打红一批与本次改动毫无逻辑关系的门禁**。实录：把 me 页 6 条读数
  迁进登记表后删掉 `syncTabBarUnread`、并在 `behaviors: [...]` 里追加了一项 ⇒
  `check:tabbar-custom` 的「页面直调模态记账」「我的页漏挂宿主 behavior」两条锚点同时失效。
  **判据与做法**：
  1. 收尾跑 `npm run check` 若报「自测锚点失效」，**不是业务回归**——去脚本 `MUTATIONS` 表里改锚点；
  2. 改完锚点**必须让该变异重新"能被打红"**（锚点取的新文本要在注入后真的触发那条规则）；
  3. **锚点要选"唯一上下文"，禁用会命中多处的裸行**：实录 `"      this.refreshReadouts()\n"`
     在文件里出现两次（onShow 与登录态订阅），`String.replace` 只替换**第一处** ⇒ 变异打在错的
     调用点上、断言随之静默失效（表现为「注入违规后仍全绿」，最难查）。取"onShow 首两行"这类
     带相邻上下文的串；并在注入前加一条 `if (me.indexOf(anchor) < 0) problems.push('锚点失效')`，
     让锚点漂移**显式报错**而不是静默。
- **给"行为门禁直跑的产物"加 import ⇒ 必须同步该门禁的 require 桩（2026-10-03 实录）**：
  行为门禁把被测页面 `tsc` 到临时目录后在 VM 里 `require`，未登记的依赖会直接抛
  **`未桩的依赖：../../services/xxx`**（`check-first-frame-behavior.js` 的 `stubs` 表）。
  实录：把快讯页 `isDarkMode` 收敛为 `resolveEffectiveTheme()`（新增 `services/theme` 依赖）⇒
  该门禁 5 条断言全红，看起来像"我把快讯页改坏了"，实际只是**没给新依赖加桩**。
  **判据：行为门禁的红是"未桩的依赖"字样时，先补桩再怀疑业务。**
- **写新门禁的标准三件套 + 三个坑（2026-10-03 实操，`scripts/check-page-enter.js` 可作模板）**：
  结构 = **S 组静态**（扫源码：fail-closed 命名形态发现 + 豁免/登记表写明理由）+ **B 组行为**
  （`execFileSync(tsc --outDir tmp)` 现编译 → `vm.runInNewContext` 直跑产物 → 假宿主断言）+ **M 组变异自测**
  （注入违规必须被拦）。注册 = `package.json` 加 `check:xxx` 并挂进 `check` 链。
  1. ⛔ **`check()` 里必须调 `pass()`**：只 `try { fn() } catch { fail() }` 的写法会让"通过"静默无输出，
     计数与输出都对不上（本轮先漏了，表现为"13 条断言只打了 8 条"）——**门禁的可见性与断言同等重要**；
  2. ⛔ **跨 VM 断言先展开**：VM 里造出来的对象原型与本域不同，`assert.deepEqual` 直接报
     "Values have same structure but are not reference-equal" ⇒ 比较前 `{ ...patch }` 转成本域对象；
  3. ⛔ **块注释里禁出现 `*/`**：`/** 表（pages/*/readouts.ts） */` 会被 `*/` 提前闭合 ⇒ 整脚本
     `SyntaxError`（先跑 `node --check` 再跑门禁）。
  另外：门禁里"发现规则"要 **fail-closed + 变异自测**（如"像读数的导出函数必须有 TTL 缓存，否则登记理由"），
  否则规则会随命名习惯漂移而**静默失效**——"门禁绿"与"规则真的在工作"是两件事。
- **收尾固定顺序（两条都要看，缺一条就会漏）**：
  `npx tsc --noEmit` → `npm run mirror:js -- <显式 ts 路径…>` → `npm run verify`，
  然后**同时**核 `verify` 的退出码（须 0）与 `grep -cE "FAIL|✗" <log>`（须 0）。
  只看"没报错"不够：门禁链是 `&&` 串联，**中间一道红会让后面的门禁根本不执行**（本轮实录：
  `check:tabbar-custom` 一红，后面 22 道门禁全没跑，看起来"只剩一个问题"）。
- **并发编辑探测（本仓常态，上手第一件事）**：`ls -lT <你将要改的文件>`（mtime 是不是刚刚）+ `date`
  + `git status --porcelain`。**mtime 在最近一两分钟内 ⇒ 有别的会话在写同一批文件**；此时：
  ① 只用 `Edit`（字符串精确匹配，不匹配就失败）**，⛔ 绝不用 `Write` 覆盖整文件**；
  ② 动手前先跑一次基线（`tsc --noEmit` + `npm run check`），**把已有的红事先记账**；
  ③ 收尾汇报时用 `git status --porcelain | grep -E "<我的文件>"` 与 `<别人的文件>` 分组，
  明确区分"我改的"和"不是我改的"——否则别人在飞的红会被当成你的锅。

## 4. 根因纪律（本篇最重要的一条）

**症状 ≠ 机制。** 先判定现象属于哪一类，再进对应怀疑域：

| 现象特征 | 优先怀疑 | 常见误入 |
|---|---|---|
| 元素「跟着手指但不变位置/被拉扯/尺寸在变」 | **盒模型**：绝对定位同时有 `left` 与 `right`（或 `top` 与 `bottom`）→ `auto` 宽/高被约束反解 → 元素被拉伸 | transform / 动画（改了没用） |
| 元素「一跳一跳 / 结束瞬移」 | transform 与 CSS 动画关键帧互相覆盖（定位禁用 transform，见 AGENTS.md） | 数据抖动 |
| 「首次正常，交互后错」 | 初值与自然尺寸重合掩盖了错误（如量测点写回坐标） | 状态管理 |
| 「切页时闪一下 / 先消失半秒再出现」 | **显隐靠轮询推断**（定时器 + `getCurrentPages`/`selectComponent` 猜栈顶）：`attached` 时页面树未就绪必漏判，只能等下一次 tick 纠正 → 改 **`pageLifetimes.show/hide` 事件驱动**（show 立即渲染、hide 立即收起并停 tick） | request/渲染性能 |
| 「被别的层盖住 / 拖到不该去的地方」 | **同一约束两处口径**（CSS 默认位避让了某家具，JS 钳制没避让）→ 钳制与默认位同口径（`getDraggableBounds` 的 `extraTopInsetPx`/`extraBottomInsetPx`）；**别动不动抬 z-index**——压过 tabBar 会吞掉 tab 点击 | 单纯调 z-index |
| 「静默无效果，无报错」 | 未注册 token（背景透明 / 颜色继承）/ 样式隔离（组件内不继承 app.wxss class） | 后端数据 |
| **「底部/某处图标完全看不见，但选中后又能看见」** | **生成物本身是空白的**：生成脚本的成功退出码骗人——渲染器支持哪个图元、不支持哪个图元，是**静默**的（真例：ImageMagick 无 librsvg 委托时用自带 MSVG 渲染器，**只渲 fill、忽略 stroke** ⇒ 全部描边态图标变全透明，而选中态是实心态恰好逃过）。**先解码产物数墨迹像素**（`scripts/tabbar_assets.py` 的 `ink_stats`），别去查 tabBar 配置/主题/缓存 | 查 app.json 配置 / 怀疑主题没生效 / 怀疑缓存 |
| 「一条条内容看不出边界 / 白卡白带"消失" / 页面一片白」 | **画布与容器同色**：`page` 默认底色 `--color-bg`，浅色下与 `--color-card-bg` 同为 `#ffffff` ⇒ 白落白。先查本页有没有显式声明 `page,.{x}-page { background-color: var(--color-bg-secondary) }`（`npm run check:surface` 就是查这个），**别急着加边框/阴影硬凑**；要加边界也走全局 `.surface-band`/`.surface-card` | 调间距 / 加描边阴影 / 怀疑渲染引擎 |
| 「首张白卡顶端多出一条灰边 / 元素与容器顶端总有缝」 | **"间距"被写成了"每张卡的属性"而不是"卡与卡的关系"**：修饰类上写 `margin: var(--space-3) 0 0` 时**首卡也吃这个上边距**（真例·2026-09-11 计时页 idle 卡顶灰带）。修法 = 修饰类只留零边距，间距交给**相邻兄弟规则**（`.a + .a { margin-top: … }`），卡序由结构表达——禁给首卡另写"我是第一张"标记类（同 §4 推论 3） | 调 padding / 怀疑卡片原语 |
| 「某片区域要能看到背景但不能点 / 浮层把下面的内容挡住了」 | **约束优先用"结构上无节点"表达，而不是 `pointer-events` 壳**：把根节点收成"可见物本体的尺寸"（如居中胶囊 = 根节点本体），空出区域自然无节点 = 可透视 + 不可点击，且不与其他引擎要求打架（真例：全宽壳 + 根 `pointer-events:none` 会与 Skyline 官方「tabBar 根节点须 `pointer-events:auto`」正面冲突，而"子元素 auto 能否在 none 内重新命中"是未验证行为）。**居中禁 transform**：`left: calc(50% - 宽度/2)`，把 transform 留给动画（两模型不混用） | 调 z-index / 加透明遮罩 |
| 「切页动画不播 / 一闪就到」 | **靠"两段 setData（先渲染旧态、下一帧切新态）"制造位移或缩放**：中间那帧是否真正上屏不受控（会被合并成一次渲染）。切页类（tab 页切换 = 目标页重建、旧实例销毁）只能靠**挂载关键帧**：首帧一次 setData 给出终态 + 方向/来源标记，元素挂载即播放（元素被复用时"加类"同样触发动画），终态天然正确（动效规范第 8 条）。跨实例要动的另一侧（如"上一格收起"）由**模块级单例 store** 记住来源；**动画类只挂"确实由用户动作引起的状态跃迁"**（`fromIndex = -1` 的冷启动/从非 tab 页返回一律静态点亮，否则每次回来都重播一遍动效） | setData 性能 / 过渡时长 |
| 「上云/同步类功能静默无效果」**但后端接口在线** | **待同步队列是"增量触发器"而不是事实源**：只由写操作入队 ⇒ 功能上线**之前**就存在的数据，id 从未入队、永远不上报（必须配一次性存量回填 + `*_FLAG_KEY` 标记）。另一半是**载荷合法性**：服务端 `validate()` 会整条拒，而客户端常写「rejected 也一并清队」⇒ 缺陷静默蒸发（真例：删除上报传 `ts=0/amount=0`，撞 `amount>0 && ts>0`，删除永远到不了云端）。**判据：墓碑/删除类上报必须携带原始业务键** | 后端没部署 / 后端接口坏了（先做**只读探测**：401 = 接口在线，别急着怀疑后端） |
| 「我没删过的东西少了 / 自己变了」 | **一次性迁移的破坏性动作**（清退/裁剪历史数据、改名归一化）+ 后续 seed 标记已置位 → 永不自愈。先翻 `services/*` 里的迁移函数与 `*_FLAG_KEY`，别从业务逻辑找 | 后端接口 / 用户误删 |
| 「一件事被切成两块」（底部按钮自成区域 / 同一信息出现两遍） | **一次构图/一次文案被表达了两遍**：同色表面的操作区另起一块底色（改结构，把操作区收进同一表面）+ 内部细线分层；名称已含的信息再抄一行摘要（按"信息增量"条件渲染，不是 `display:none`） | 调颜色 / 调间距 |
| 「一行字被拆到两端 / 中间一大段空白 / 读一行要跨两道视线」（如 `x 分钟=……19:33~19:40 >`） | **把逻辑上不可分的一段文本当成了"两列"**：某子元素带 `margin-left: auto` 或容器 `space-between` ⇒ 等式/句子被拆到行首行尾。右对齐的承载要给**容器**（`justify-content: flex-end`），不是给子元素加自动外边距（后者语义是"我脱离前面的流"）；共享同一列表语言的**兄弟页要同改**（本仓真例：计时页补救区 ↔ 息屏记录页，见 43 §15.1） | 调字号 / 调间距 / 改文案 |
| 上一条**修完之后**换了个症状：**「一侧大片留白 / item 体积小、布局失衡」**（如整组贴右 ⇒ 行首 ~400rpx 无人区） | **先判「这一行承载几件独立事实」，再谈对齐**。上一条的修法（右对齐给容器）只对"两列"成立；当行内容本身只有**一件事实**（一个等式 / 一句不可分的话）时，贴左或贴右都必留半行空白——**改对齐 = 换姿势，改信息模型 = 治病**。出路两条：① **拆成两件独立事实**（各自成完整信息块 ⇒ 才允许 `space-between` 两端锚定；列要 `flex-shrink:0` + 列内固定 gap，"值 + 提示词"永不被拆开）；② **收窄容器**。同时审「每行都几乎相同的字段」是否该整列退役（区间终点 ≈ now ⇒ 24h 窗口内每行终点几乎相同 = 零信息增量，降噪删重复、但**识别信息如提示词必须留**）；另：行高恰好卡 `--touch-target-min`(88rpx) 时用户感知 = "内容挤在行里 = item 体积小"，内距抬一档让内容自身撑开。真例：息屏记录行「一个等式 → 两列」（左锚起点时刻 = 行身份 + 动作对象 / 右锚距今时长 = 后果），见 43 §16 | 反复调 `justify-content` / 调列宽 / 加分割线或底色块 |
| 「用户看不懂这一屏/这一串数据是什么」（文案"简洁"到丢了识别信息） | **降噪删过头**：把"来源/身份"类说明当成冗余删了。**降噪删的是重复信息，不删识别信息**——行内容来自用户不可见的后台机制（息屏段、系统事件、同步队列）时，区头必须有一句来源说明；"内容自明"只对用户自己主动产生的数据成立（真例：补救区副文案曾被压成"点一条，从那时接着计"，见 43 §15.2） | 加图标 / 加弹窗 / 写更多解释文案 |

| **「背景/元素发虚、像被放大过」** | **呈现尺寸超过了资产像素**：先算 `1rpx` 在该机型上的物理像素（最坏 = iPhone 15 Pro Max 1290px 宽 ⇒ 1290/750 = **1.72px**），拿"呈现 rpx × 1.72"与"资产 px"比——超过 **1.25×** 上采样即判糊。真例：300px tile 撑 480rpx ≈ 755px = **2.5×**。**别先怀疑渲染引擎 / opacity / PNG 压缩**（换编码只会更糊） | 提高 opacity / 换渲染器 / 重压 PNG / 怀疑渐变层 |
| **「同一个图案在屏上反复出现 / 一屏看到好几次同一样东西」** | **变体数 < 屏上可见槽位数**：先量"屏上**真正可见**几个槽位"——`grid` 宽度可能大于视口（真例 1440rpx vs 视口恒 750rpx ⇒ 第 3 列**整体出屏**），**出屏的列不算**；8 个可见槽位配 4 个变体 ⇒ 必然重复。**别去加"随机偏移/错位"这类补丁**（掩盖而非消除），也别顺手改 tile 显示尺寸（那是全局契约，会连带改别的页） | 加 transform 偏移 / 改 grid 宽度 / 缩小 tile 尺寸 |

| **「某个控件像一条线/一块白条把背景切开」**（尤其底纹/渐变画布上的通栏元素） | **材质跟错了画布**：`--color-bg-secondary` / `--color-card-bg` 是**灰画布**上「与画布异色的白面」语言；搬到**彩色画布**（wash 渐变 + `.page-pattern` 涂鸦）上就变成一条比画布更亮的实心带，把底纹从中间**截断**。判据 = **材质跟着「它坐在什么上面」走，不跟着「它是什么控件」走**：坐在画布上的无表面控件走 `--color-canvas-groove`（轨道）/ `--color-canvas-mark`（次级刻度），浅色淡墨、**深色必须淡白**（深色 wash 太暗，淡墨隐形）；量程/标注类标记仍走 `--color-muted`（与数字同色）。**作用域必须收窄到画布态**（如 `.dt-page--live`），白卡/灰画布上的同族控件保持不透明面。**别去调条高/圆角/透明度数值**（多轮实测调不动观感） | 调条高 / 调圆角 / 调 opacity 数值 / 加 border / 加阴影硬凑 |

| **「内容被顶部那条原生导航栏截断 / 想让画布或图片上到状态栏」** | **原生导航栏画在 WebView 之外**——它是微信自己绘制的实心带（含状态栏），页面内容永远画不到它下面，改 CSS/z-index 一概无效。唯一路径 = 该页 `navigationStyle: "custom"`（自绘导航栏），微信把整屏交给页面（**页面 0 点 = 屏幕 0 点**）。几何走 `services/viewport.ts` 的 `getNavBarMetrics()`（**唯一权威实现**，禁页面重算那三个数）；自绘导航容器必须 `position: relative; z-index: 1`（全屏底纹是 `z-index:0` 的定位元素，会画在静态流内容之上）；custom 页面 `100vh` = **整屏高** ⇒ 顶部让位必须显式扣掉（`calc(100vh - var(--dt-nav-h))`，别用 `min-height:100%`——百分比高度在原生 scroll-view 内的解析失败是静默的） | 调 z-index / 给页面加 padding-top / 用 `setNavigationBarColor` 改背景色（只能做到"色带接得上"，图片/涂鸦上不去） |

| **「控制台在某类页面刷同一条红字」**（真例：进任意**非 tab 页**刷 5 条 `setTabBarStyle/setTabBarItem:fail not TabBar page`，而 tab 页干净） | **平台 API 的"作用域"限制**：先确认该 API 是否只在特定页面类型可用（原生 tabBar 系列**只在其所属 tab 页**可调），再查调用方是不是"不分页面类型地统一调用"——`themeBehavior` 每页都接（正确），错的是它调平台 API 时没问「这页有没有 tabBar」。判据点 = `constants/tabbar.ts isCurrentPageTab()`（由 `TAB_ITEMS` 派生） | 怀疑时序抖动 / 怀疑 Behavior 接错页面 / 只把 `console.error` 改成 `console.warn` 掩盖 |
| **「某个入口区再也回不来 / 整页锁死，只能退出小程序重进」**（真例：搜索改词后结果变空 + 下滑收起顶部控件带 ⇒ 控件带（整页唯一导航入口）永不恢复） | **恢复通道只依赖「边沿事件」**：状态由滚动/手势边沿驱动，而边沿只在特定内容状态下存在（scroll 事件只在内容可滚动时产生）⇒ 内容一变通道整体消失，状态进**吸收态**。先问该状态有没有**电平判据 + 自愈触发点**（`reconcileListControls` 类：判据「收起 ⟺ 内容可滚动」），别去加"再点一次就能恢复/加个重试按钮"的补丁 | 怀疑渲染卡死 / 怀疑 setData 失败 / 加一个兜底按钮 |

| **「用户反复在某个输入框里输该控件不支持的东西 / 某入口点开后"根本不是我想的东西"」**（真例：用户多次在城市选择面板的搜索框输入「附近 50KM」，而该框只匹配城市名） | **入口文案的语义域 ≠ 落地控件的语义域**。入口（页签名 + 控件带胶囊）渲染的是「附近300km」= **范围**语义，点开却是「选择城市」；面板内唯一的范围入口半径**写死默认档**且与左上角标签不同源（**两份真值**），点它还会把用户想要的 50km **重置回 300**（**反向动作**）；能改档的真入口在**另一个面板**（筛选 → 距离范围）。⇒ 用户的意图无处表达，只能在唯一可见的输入框里"打字表达"，而空态只说「未找到相关城市」。**先查三件事**：① 入口文案承诺的是哪个维度 ② 落地控件能操作的又是哪个维度 ③ 用户想要的目标状态有没有**任何**可见入口。**别**归因为"用户不会用" / "提示不够明显" / "该给搜索框加模糊匹配" | 给搜索框加"聪明"解析（把操作项混进过滤结果 ⇒ 结果列表变命令列表，且自由文本永远匹配不全：`50`/`50公里`/`附近50`）/ 加一句用户不会读的提示 / 加引导弹窗 |
| **「顶部那一条在滚动后变白 / 某条实心带把画布切开」**（真例：快讯页自定义导航栏，用户报「往上翻页后标题区 + 状态栏又变白」） | **遮挡物的材质选错了**。坐在画布上的固定顶栏确实需要"不透明遮挡"才挡得住从下面穿过的内容，但材质**不能拿页面底色（`--color-bg`）去填**——占位物必须等于**「它遮挡处本该显示的东西」**，即同一份画布。三件配套：① 渐变按**整屏尺度**绘制（`background-size: 100vw 100vh` + `position: 0 0`），否则三站色被压进 ~88px 高的导航栏（顶部一条出现屏上别处没有的横向色带）；② 涂鸦副本用 `absolute` 而非页面底纹的 `fixed`（顶栏锚在视口原点 ⇒ 与页面 tile 网格像素级对齐；fixed 会叠成 0.10 → 0.19 重影），定位覆盖用三 class 写法压过本页那条 `position: fixed` 变体；③ 整层**只过渡 `opacity`**（涂鸦副本的0.10/0.15 沿用全局原语 ⇒ 本页零第二份主题声明；`background-color` 过渡在两个材质之间必经"半透明的白" = 起点跳变）。副本**直接复用页面那份 tile 数据**（"同源"优先于"省节点"）。同族：43 §67 画布上的控件禁不透明白面 / 38 §0 第 0 条容器边界。详见 47 §7.12 | 调 z-index / 加 border / 调透明度数值 / 只改颜色 |
| **「遮罩/弹出框只遮住一部分页面」**（真例 2026-09-30：门店列表页「过滤/排序」弹出框的遮罩**只遮住底部列表**，操作栏 + 页内 Tab + 导航栏全没被遮住，**而系统状态栏区域正常**） | **层序越界**（不是"遮罩没渲染"）。三步取证：① `npm run check:z-stack`（直接点名破坏了哪条阶梯）；② `grep -n "z-index" <相关 wxss>` 看那些层用的是 token 还是裸数字；③ **比对"带"**——遮罩必须高于**一切常驻层**（`chrome < dock < overlay-mask`）。真例根因 = chrome 组写死 `z-index: 60` 压过同页筛选遮罩（50/51）；**"状态栏区域正常"是该类的高置信线索**（覆盖层从状态栏下沿才开始渲染 ⇒ 状态栏那一条恰好没被压住）。**别只把那个数字改小**（层序是全局有序清单，见 `docs/agents/03-style-system.md`「层叠阶梯」），也别加 `!important` 或改成 `9999`（后者只会压过遮罩更彻底） | 怀疑遮罩节点没渲染 / 加 `!important` / 把值改成 9999 / 给遮罩加 `position:fixed` 重写一遍 |
推论 1：`position: fixed|absolute` 元素必须处于**两种互斥定位模型之一**——
锚定位（只有 `right`/`bottom`）或坐标位（内联 `left`/`top` + 一个 class 显式
`right: auto; bottom: auto`）。"默认锚定 + 拖动改坐标"是合法需求，但切换必须显式。

推论 1b：**浮层位置默认固定锚定位，拖动 = 可选能力（禁无差别开放）**。
2026-09-10 计时悬浮小窗实录：七~十三轮为"自由拖动"反复付代价（盒模型拉伸 →
可拖进 tabBar → 手势/持久化/误触抑制状态机），十四轮用户一句"不允许自由拖动"
让这些分支**全部失去存在理由**——`timer-float.ts` 370 → 150 行，位置回归纯 CSS，
组件零 JS 几何。**判据：一条能力的收益 < 它为系统引入的分支数时，删能力比修分支更彻底。**
（确需拖动时先读 `docs/agents/43-dance-timer.md` §10.2/§10.6：两模型互斥 +
钳制与 CSS 默认位同口径 + 门禁全绿。）

推论 2：**能用平台事件表达的状态，禁用定时器 + 启发式推断**（组件所在页可见性
= `pageLifetimes`；页面数据刷新 = `onShow`；滚动/尺寸 = 对应事件）。轮询版既
引入随机相位延迟（闪一下），又让页面栈下层实例白跑。

推论 3：**同一约束只许一个口径**。凡是"CSS 里避让了某家具（tabBar/安全区/导航栏）、
JS 里又另算一套边距"的写法，迟早有一处漏。公共地图：`services/viewport.ts`
（`getViewportMetrics`/`getDraggableBounds`/`clampToBounds`/`rpxToPx`/
`TAB_BAR_HEIGHT_RPX`）。**同款推广到"位置/顺序类标记"**：凡结构本身能表达的事实
（末行无分隔线 = `:last-child`、列表首项 = `:first-child`、空态 = 数据为空），
禁再手写一个"我是最后一行/我在最前"的标记类——手写标记与行序脱钩后**静态检查查不出、
只有肉眼能发现**（真例：me 页 `.setting-item-plain` 留在「我的贡献」上，其后插入
「计时器」导致两行之间少了分割线，见 38 号文末）。

## 5. 修复落码习惯（生产级）

- **多分支文案/出口 → 声明式目录 + 纯解析器 + 零逻辑直渲（2026-09-30 空态实录，通用）**：
  凡"同一个位置要按 N 种原因渲染 N 套文案 + 不同出口"的地方（空态 / 报错态 / 提示条 / 引导态），
  **禁止**在 `wxml` 里堆 `wx:if/wx:elif` 条件链——判断写模板里、文案散模板里、同一事实两条分支
  各写一套、**新增一种原因只能改模板**（而模板是本仓唯一没有测试保护的层）。样板 = 三件套：
  ① **声明处**（`utils/xxx.ts`）：`CASES`（原因 → 文案 + 行动项 id 列表）+ `ACTIONS`（行动项 →
  材质/文案）+ `PRECEDENCE`（**优先级显式声明，禁靠 if 顺序隐式表达**）；
  ② **纯解析函数**：按优先级逐条问判据、首个成立者胜出，末尾一条恒真兜底保证恒有返回；
  页面 `data` 初值 = 解析器对空输入的自洽输出（**禁手写初值对象** = 第二条构造路径）；
  ③ **零逻辑直渲**：模板只渲 `{{state.title}} / {{state.actions}}`，行动项按 `id` **单点派发**到
  **既有出口**（不新增业务逻辑），材质走 `btn-{{item.tone}}`（声明 tone 而非类名，零分支）。
  三条配套判据：**同一事实只许一份文案声明**（旧实现"搜索入口"与"城市浏览入口"各写一套，更常用的
  那个拿到更差的）；**优先级按"事实的绝对性"排**（任何操作都改变不了的事实排前——"该地没收录"要排在
  "筛选太严"之前，否则让用户去放宽筛选而放宽后依然为空）；**fail-safe 方向 = 退回改动前行为**
  （依赖的集合未知时不得给出更强的新断言；本轮 = 覆盖城市集合为空时不得判"暂未收录"，否则把
  「我们不知道」说成「我们没有」）。
  ⚠️ **触发点 = 每个输入源一处，且要数清楚有几个**：本轮实测漏了第二个——覆盖城市集合
  （`GET /venues/cities`）晚到（冷启动直连搜索框 / 弱网兜底）时必须重算，只在"列表提交"处派生
  会停在旧空态；后来加了行政区划名录又多一个（`loadKnownRegions`）。**做法：把「谁能让这个
  派生结果变化」逐一列出来，每个来源各接一处，并在门禁里逐处断言**（变异：删掉那一处调用即红）。
- **「同一个概念两种写法，比较前必须先归一」（2026-09-30 空态第二轮实录，跨域通用）**：
  用户输入「杭州」，平台存的是「杭州市」——两处**都对**，但直接字符串比对必然失败，
  于是把**已覆盖**的城市误判成"未收录"（行为门禁 E5 拦下）。修法 = 引入 `resolveRegionName`
  单点归一（用户写法 → 规范名），**文案渲染与覆盖判定都必须吃它的输出**，禁各自再处理一次。
  判据：**凡"用户自由输入"要与"库里标准值"比较的地方，先问一句"这两种写法等价吗"，等价就必须
  有一个归一函数，且所有消费方（显示 / 比较 / 上报）都从它取值。** 同族高发地：城市名带不带
  「市」、手机号带不带 +86、日期带不带时分。
- **变异测试的变异本身要"真的破坏属性"（2026-09-30 实录）**：变异「只加一行 `_x = 1`、不动
  被断言的调用」= **假变异**——属性没被破坏，门禁当然绿，于是被误判成"断言漏检"。
  三种失败必须区分开：① **锚点失配**（old 串不在文件里 = 变异没打上）；② **变异未生效**
  （打上了但没破坏属性，如只加行）；③ **真漏检**（属性被破坏但门禁仍绿）。工具必须把①②
  显式报错，只允许③算作门禁的失败。⇒ 写变异 harness 时：替换后先 `assert mutated != original`，
  正则类变异要单独处理锚点检查（不能用字面量 `in` 判断）。

- **单一权威实现**：几何（视口/安全区/钳制/锚点）走 `services/viewport.ts`、
  `utils/popover.ts`；禁组件内自造 `wx.getSystemInfoSync()` + 私有边距常量（漏安全区 + 每帧跨层读窗口）
- **「一个状态 = 一份真值 + 一个写入点 + 一个判据」三件套**（2026-09-30 距离范围实录，通用）：
  同一个业务值出现在多处时，任一处自成真值就是**静默错误**（tsc 与门禁全绿，只有用户撞得到）。
  四条落地形态——
  ① **文案与状态同源**：显示该值的**每一处**（左上角标签 / 面板 chip / 页签名 / aria）必须由**同一个
  派生表达式**产出。真例：`nearbyLabel` 写死 `DEFAULT_RADIUS_KM`，而标签是
  `formatRadiusKm(effectiveRadius)` ⇒ 用户选 50km 时面板说「附近300km」，**并据此去找"能改档的地方"**；
  ② **配置单一声明处**：档位/枚举只有一份定义（`RADIUS_QUICK_OPTIONS`）；消费方**经 property 注入**
  ——**组件禁 import 页面业务常量**（反向依赖），也禁自写字面量数组，否则两处档位必然漂移；
  ③ **写入点唯一**：用户主动改该值的入口**全部转发到一个方法**（`selectRadiusKm`），副作用（无定位先
  请求定位 / 复位降级标记 / 重拉列表）随之单点收口——同 `setSortMode`。漏一处即 09-20 那种
  「三处调用点漏改 ⇒ 接口 500」同族事故；
  ④ **判据唯一**：该状态的"是不是它"只允许**一个谓词函数**（`isNearbyScope()`）。真例：抽出前
  `refreshCityLabel`（认任意档）与 `refreshFilterDerived`（只认默认档）各写一套 ⇒ 50km 档时
  **面板入口不高亮、无法回显当前状态**。判据单点与 `getEffectiveRadius/getEffectiveCity` 同族。
  配套一条**兜底纪律（空态必须给出路）**：任何"零结果面"只宣布"没有"就是把用户留在死胡同（同 §4
  「吸收态」一族）。真例：城市搜索空态原只有「未找到相关城市」→ 改为三档分派：含距离意图且**命中
  档位** ⇒ 一步可点的行动项；是数字但不在档位 ⇒ 明示可选档（**不猜、不静默取整**）；其余 ⇒ 说明
  本框只搜城市名 + 指路真入口。**判据：空态要给动作，不给解释。**
  机器校验：`check:list-filters` **D 组**（五条断言 + 8 条变异测试）。

- 顺带清理同域陈旧注释/命名（如"吸附"已退役却留在注释里）
- **高频事件一律「记账 + 单次武装 + 到期复检顺延」**（2026-09-10，触底自愈定时器 60Hz 重排根因）：
  `bind:scroll` / `touchmove` / `input` 上「延迟到事件停止后再执行」的 debounce，旧写法是每个事件
  `clearTimeout+setTimeout`（每秒 60 次重排）——改为：事件只更新 `lastScrollAt` 类时间戳，定时器
  **已武装则原样保留**，到期回调算 `idleFor = now - lastScrollAt`，`idleFor < delay` 才顺延

  内容可滚动时产生），内容一变通道就可能整体消失 ⇒ 状态进入**吸收态**（真例：搜索改词后结果变空
  + 下滑收起顶部控件带 ⇒ 控件带（整页唯一导航入口）永不恢复，只能杀进程重进；平台那次 clamp
  合成事件还会被几何静默窗吃掉）。三条硬要求：① 显式声明**电平判据**（可测量的几何/数据事实：

## 5.1 改「跳转 / 返回」类行为前的三条前提（2026-09-30，详情页「下一家」改 redirectTo）

任何改动「页面怎么进 / 怎么出」的改动（`navigateTo` ↔ `redirectTo`、加栈底回跳、某页改 tab 页……），
动手前必须核完这三条，缺一条就会引入静默缺陷：

1. **目标页是不是 tabBar 页** —— `wx.navigateTo` / `wx.redirectTo` **都不允许**跳 tabBar 页
   （只能 `switchTab`，且 `switchTab` 会**清掉所有非 tab 页**）。先看 `app.json` `tabBar.list`。
2. **源页被销毁时有没有清理** —— `navigateTo` 只压栈（走 `onHide`），**`redirectTo` 会销毁当前页**。
   ⇒ 从 `navigateTo` 改 `redirectTo` = 把一条"只在 onHide 发生"的路径，变成"也会在销毁时发生"，
   必须确认清理钩子存在且完整。
   ⚠️ **本仓页面一律 `Component()` 构造，销毁走 `lifetimes.detached`，不走 `onUnload`**
   ——`grep onUnload` 查"有没有清理"会**假阴性**（实测 venue-detail 一个 `onUnload` 都没有，
   但 `lifetimes.detached` 里有网络订阅解除 + 折叠通道复位）。
   **正确查法：`grep -n "detached()" <page>.ts`。**
3. **新页 `onLoad` 的栈底判据会不会被改变** —— 本仓详情页 `onLoad` 有
   `getCurrentPages().length === 1` 的**分享落地分支**（栈底 ⇒ 存路径 + reLaunch 首页 + 回跳）。
   `redirectTo` 后栈深不变（仍 ≥2）⇒ 不误触；但**若改成 `reLaunch` 就会误触**（重建栈底）。
   判据：**改跳转 API 时逐个走查新页 `onLoad` 里所有读 `getCurrentPages()` 的分支。**

**顺带的设计判据（比上面三条更值钱）**：**同一个手势的两端必须表达同一种导航模型。**
"上滑 = 继续往下刷"是**流心智**；用压栈实现会强迫"左滑 = 回上一层"成为**栈心智**，
两端对同一个"前进"动作给出矛盾预期（用户上滑 8 家后要左滑 8 次才回列表，且第 10 层起
`navigateTo` **静默失败**、用户侧只表现为"滑了没反应"）。
判据：**入口手势承诺"继续前进"时，落地必须用"替换当前页"而不是压栈**——返回即回到这条流的起点。

**背景**：本轮由 iOS 侧滑返回手势调研引出。该手势是**平台能力边界**（归属微信客户端原生层，
JS 层既监听不到也拦不住；`disableSwipeBack` 自 7.0.5 废弃；`wx.enableAlertBeforeUnload`
对手势返回无效）——**不存在"适配手势"这个选项，只有"在返回路径上做防御"**。
平台事实与本项目两条防御的落点见 `docs/agents/04-navigation-architecture.md`
「iOS 侧滑返回手势的能力边界」。

## 5.2 改「交互形态 / 关闭时机」前的两条前提（2026-10-03，列表页排序面板「选中即关」）

**缘起**（用户提问）：「选中一个排序项后，是否应该主动关闭这个弹窗，而不是让用户再手动关？」
结论 = 合理，但**只改一半会比现状更差**。

**前提一 · 先归类，再看同页同类控件的行为是否一致。**
关闭时机由「这次点击是否构成**一个完整决策**」决定：

- **N 选 1 单选器** ⇒ 一击即终态 ⇒ **选中即关**（选项即提交）；
- **多维表单** ⇒ 一次点击只是设置过程中的一步 ⇒ **保持打开**。

⇒ **同一页里同类控件行为不一致时，先怀疑「归类错」**（排序当时被归进了「筛选」族，而同页城市
选择器早已是「选中即关」）。**查法**：grep 同页其他选择器的关闭动作落在哪几条分支里
（例：`cityPickerVisible: false` 出现在城市选择器的四类 select 分支，一条不落）。

**前提二 · 改动前先查「同一控件的另一个设计」是否与它耦合。**
例：排序按钮当时是「已激活 ⇒ 点击复位回推荐」，与「面板选中即关」**互相冲突** —— 只加关闭会让
「改选另一个排序」从 2 击变 **3 击**（点按钮被拦截去复位 + 白拉一次列表）。
⇒ 凡「一个控件同时挂着**入口动作**与**选项动作**」的双载语义，改任一侧**必须同轮审另一侧**。

**落码要点（可复用）**：
- 关闭动作放进**状态单点写入方法**内（如 `setSortMode`）⇒ 副作用随单点收口，且「未落定路径」
  （定位失败等 early return）**天然不关面板**，不需要额外特判。
- 关闭必须**先于幂等短路**（点当前已选项 = 「确认并收起」，与值是否变化无关）；同时撤掉**调用方
  自己**的幂等短路，否则「点当前项」被它吞掉、连面板一起不关。
- 门禁**双向**钉：该关的必须关（含点当前项）+ **不该关的不得关**（未落定）。本轮一条 check 内四个
  方向，变异 5/5 各命中不同断言 ⇒ 一条 check 覆盖多方向时，**变异要逐方向打，别只打一次就收**。
- ⚠️ **变异锚点必须唯一**（2026-10-03 二次踩）：两段**逐字相同**的代码块会让
  `str.replace(old, new, 1)` 打在**另一处**（本轮打在了同文本的 chip 引导块上），输出看起来像
  "断言漏检"，其实被断言的代码纹丝不动。**首选修法 = 抽单点**（两处共用同一方法），从根上
  消除歧义；退而求其次才是加深锚点上下文。**看到"变异没拦住"时，先怀疑锚点，再怀疑断言。**
- ⚠️ **凡「把隐藏的东西改成常驻 / 默认展开」的改动，动手前先清点它原先躲过了哪些缺陷**
  （2026-10-03「距离档位行默认展开」：暴露出此前被"默认折叠"掩盖的静默 `return`——无定位时
  点档位毫无反应）。同一 section 内**同族控件对同一前提失效，表现必须同款**（chip 置灰 +
  toast ⇒ 档位同款，而不是隐藏）。
- ⚠️ 一条断言若"两处任一满足即可"，它测的就不是它想测的那一处（2026-10-03：默认展开要
  **data 初值与 show 复位分别断言**，写成"源码里存在一处 true"会被另一处满足 ⇒ 只改一处测不出来）。
  切段用 `slice_between`，别对整个源码文件做 `re.search`。
